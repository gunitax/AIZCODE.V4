# План реализации универсального HTTP-сервиса объектов (`objects`)

> **Для агентов-исполнителей:** REQUIRED SUB-SKILL: использовать
> superpowers:subagent-driven-development (рекомендуется) или
> superpowers:executing-plans. Этапы выполнять строго по порядку: каждый этап
> заканчивается загрузкой расширения в рабочую базу (по явному ОК пользователя)
> и проверкой своих запросов. Прогресс — чекбоксы; результаты RED/GREEN
> записывать текстом под чекбоксами этапа.

**Цель:** один сервис описывает, ищет, читает и создаёт справочники и
непроведённые документы 1С; контракт счетов заменён маршрутом `POST /object`.

**Архитектура:** логика в общих модулях расширения уже обобщённая
(`СчетаМагазинаМетаданные` — описание по метаданным, `СчетаМагазинаДанные` —
преобразования, поиск, чтение); привязка к счёту локализована в нескольких
точках и заменяется параметром «Вид.Имя». Обработчики HTTP-сервиса
реализуются поверх модулей, транспортные помощники (JSON-ответы, формат
ошибок, журнал регистрации) уже есть.

**Стек:** русский BSL, выгрузка Конфигуратора (формат 2.21), Apache-публикация
`/bsp-demo2`, проверка запросов — `curl.exe`/REST Client (Node.js на машине
нет). Сборка `.cfe` — батником Конфигуратора на одноразовой базе.

**Спецификация:**
[docs/superpowers/specs/2026-11-04-objects-service-design.md](../specs/2026-11-04-objects-service-design.md).
Исполнителю читать спецификацию вместе с планом: все статусы, форматы значений
и правила полей определены там.

## Глобальные ограничения

- Основная конфигурация не меняется; правки только в
  `src/extensions/СчетаМагазина/`.
- Русский BSL; вместо «ё» — «е» (включая тексты сообщений).
- Все изменяемые файлы — UTF-8 с BOM, переводы строк CRLF.
- Совместимость расширения `Version8_5_1` не менять; состав объектов
  расширения (XML) не меняется — этапы правят только модули BSL.
- Привилегированный режим не включать; все запросы к данным — с `РАЗРЕШЕННЫЕ`.
- Загрузка в рабочую базу — изменяющая операция. Пользователь разрешил загрузки
  расширения в базу (сессия 2026-11-04) — отдельный запрос ОК на каждую загрузку
  не требуется. Пользователь также разрешил завершать чужие сеансы 1С, мешающие
  загрузке. Предохранители: не убивать процесс посреди активной загрузки
  (база портится, лечится только пересозданием); после принудительного снятия
  сеанса убедиться, что база открывается, при «молча exit 1 с пустым логом» —
  пересоздание по процедуре диагностики скилла `make-extension`. Альтернатива
  по желанию пользователя: он загружает сам в Конфигураторе
  («Расширения конфигурации → СчетаМагазина → Загрузить из файлов») и
  подтверждает словами «загружено».
- Чужие процессы `1cv8.exe` не завершать никогда; если база занята сеансом —
  остановиться и спросить.
- Каталог не git-репозиторий: шагов коммита нет, фиксация — чекбоксы и записи
  RED/GREEN в плане.
- Формат ошибок `{"error":{"code","message","details":[{"path","message"}]}}`;
  коды: `invalid_request`, `unknown_type`, `creation_not_allowed`,
  `validation_failed`, `not_found`, `forbidden`, `unsupported_media_type`,
  `internal_error` (точные тексты — на исполнителе).

## Review Focus

1. Символы `%`, `_`, `[` в `q` поиска — литералы: `q=%` даёт пустую выдачу,
   а не «всё». Проверка — этап 3.
2. UUID в верхнем регистре при чтении → `404`, как несуществующий (сервис
   принимает только нижний регистр). Проверка — этап 4.
3. Дата со смещением (`Z`, `+03:00`) → `400`, без тихого пересчёта времени.
   Проверка — этап 5.
4. `POST` к служебному виду (`Справочник.Пользователи`) →
   `403 creation_not_allowed`. Проверка — этап 5.
5. Отказ штатной проверки → `422` со всеми `details`, без записи объекта;
   `path = null`, когда поле не определяется. Проверка — этап 5, ручное
   сравнение списков в клиенте — этап 6.

## Особенности исполнения

- HTTP RED выполняется до реализации этапа, GREEN — только после успешной
  загрузки расширения: интерпретатора BSL вне базы нет (ограничение среды,
  как в прежнем плане).
- Статическая проверка XML не нужна: состав объектов расширения не меняется.
- Перед каждым запуском 1cv8 — проверка `tasklist`; чужие сеансы разрешено
  завершать (разрешение пользователя), кроме активной загрузки.
- Загрузка без явного ОК пользователя запрещена (AGENTS.md); если пользователь
  грузит сам — этап продолжать после его подтверждения.
