# AGENTS.md

Руководство для ИИ-агентов и разработчиков, работающих с этим репозиторием.

## Что это за проект

XML-выгрузка конфигурации «Демонстрационная конфигурация "Библиотека стандартных подсистем", редакция 3.2» (БСП 3.2):
- Поставщик: Фирма «1С», версия 3.2.1.569.
- Формат: выгрузка Конфигуратора («Сохранить конфигурацию в файлы»), версия формата 2.21. Это НЕ проект 1C:EDT — структура папок иная.
- Платформа: режим совместимости и режим совместимости расширения — `Version8_5_1`, управляемое приложение.
- Вариант встроенного языка: **русский**. Все имена метаданных, переменных и код — на русском.
- Лицензия кода: CC BY 4.0 (заголовок в каждом .bsl-файле).

Масштаб: ~3048 файлов .bsl, ~1,32 млн строк кода; 804 общих модуля, 108 справочников, 187 регистров сведений, 154 обработки, 166 ролей, 54 регламентных задания, 52 отчета, 25 документов, 15 подсистем, 121 общая форма, 69 пакетов XDTO, 13 веб-сервисов, 4 HTTP-сервиса, 13 перечислений.

## Обязательные правила (сводка)

1. **Веб-поиск** — если задача решалась с его помощью, в конце ответа приводить раздел «Sources:» (см. «Работа с веб-поиском»).
2. **Все доработки — в расширениях**, если явно не сказано иначе; расширения в папке `extensions/`, при ее отсутствии — создать.
3. **Кодировка и BOM** — все текстовые файлы UTF-8 с BOM, переводы строк CRLF; проверять до и после правок.
4. **Режим совместимости расширения** — должен совпадать с основной конфигурацией (`Version8_5_1`); проверять при создании и правке расширений.
5. **Никогда не завершать сеансы пользователей; автоматически не применять расширения** (см. «Запрещенные действия»).

## Структура репозитория

Корень — метаданные конфигурации, разложенные по разделам:

- `Configuration.xml` — корневой объект конфигурации (свойства, роли по умолчанию, интерфейсы).
- `ConfigDumpInfo.xml` — служебный файл соответствия версий объектов выгрузки. Генерируется Конфигуратором.
- `extensions/` — доработки в виде расширений, по одной папке на расширение (работа с ними — скилл `make-extension`). Основная конфигурация ее не использует; при отсутствии папки — создать.
- `Ext/` — модули приложения: `SessionModule.bsl` (модуль сеанса), `ManagedApplicationModule.bsl` (управляемое приложение), `ExternalConnectionModule.bsl`, `OrdinaryApplicationModule.bsl`, интерфейсы, заставка; содержит бинарные `*.bin` — не редактировать.
- Разделы метаданных (папки во множественном числе): `Catalogs` (справочники), `Documents` (документы), `InformationRegisters` (регистры сведений), `AccumulationRegisters` (регистры накопления), `AccountingRegisters` (регистры бухгалтерии), `CommonModules` (общие модули), `CommonForms`, `CommonCommands`, `Enums`, `Subsystems`, `Roles`, `Reports`, `DataProcessors` (обработки), `ScheduledJobs`, `ExchangePlans`, `WebServices`, `HTTPServices`, `XDTOPackages` и т.д.

Внутри каждого раздела на один объект метаданных приходится пара «файл + папка»:

```
Documents/
  _ДемоЗаказПокупателя.xml        <- описание метаданных объекта (реквизиты, табличные части, движения)
  _ДемоЗаказПокупателя/
    Ext/
      ObjectModule.bsl            <- модуль объекта
      ManagerModule.bsl           <- модуль менеджера
      Help.xml, Help/ru.html
    Forms/
      ФормаДокумента.xml          <- описание формы
      ФормаДокумента/Ext/Form.xml <- макет формы (элементы)
      ФормаДокумента/Ext/Form/Module.bsl <- модуль формы
    Templates/                    <- макеты
```

Имена файлов модулей: `Module.bsl` (общий модуль), `ObjectModule.bsl`, `ManagerModule.bsl`, `Form/Module.bsl` (форма), `Template.xml` (макет), `Command/Module.bsl` (команда).

Объекты демонстрационной конфигурации имеют префикс `_Демо` (например, `_ДемоЗаказПокупателя`). Подсистемы: `СтандартныеПодсистемы`, `Администрирование`, `ТехнологияСервиса`, `ИнтернетПоддержкаПользователей` и `_Демо*` для демонстрационных разделов.

## Критические правила работы с файлами

1. **Кодировка и переводы строк.** Все текстовые файлы — UTF-8 **с BOM**, переводы строк **CRLF**. При правках сохраняйте и то, и другое: без BOM Конфигуратор не загрузит файл, смешение переводов строк ломает diff и повторную выгрузку.
2. **UUID не трогать.** `uuid` в XML идентифицирует объект метаданных в информационной базе. Смена UUID = потеря данных при обновлении.
3. **`ConfigDumpInfo.xml` не редактировать руками.** Он управляется Конфигуратором при сохранении/загрузке выгрузки. После правок через Конфигуратор он обновится сам; ручные правки почти всегда приводят к полному перезаливанию конфигурации.
4. **Структуру XML не реорганизовывать.** Порядок элементов и отступы (табуляция) значимы для повторной загрузки и читаемости diff. Правки — точечные, в существующих узлах.
5. **Бинарные файлы** (`ParentConfigurations.bin`, `StandaloneConfigurationContent.bin`, картинки в `CommonPictures/`) не редактировать.
6. Изменение состава объектов (добавление/удаление файла объекта) без обновления `Configuration.xml` и `ConfigDumpInfo.xml` сломает загрузку — состав объектов меняется только через Конфигуратор.

## Соглашения по коду (стиль БСП)

Суффиксы общих модулей задают контекст вызова — при создании новых модулей следуйте той же схеме:

| Суффикс | Контекст |
|---|---|
| — (без суффикса) | сервер, серверные вызовы |
| `Клиент` | только клиент (клиент-серверный модуль) |
| `КлиентСервер` | клиент + сервер без контекстных вызовов |
| `ВызовСервера` | клиентский модуль для обращения к серверу |
| `ПовтИсп` | повторное использование возвращаемых значений |
| `Переопределяемый` | модуль, переопределяемый в конфигурации-потребителе |
| `Служебный` | внутренние процедуры БСП, не для прикладного использования |
| `Глобальный` | точка входа (в свойствах модуля) |

Прочие соглашения:
- Заголовок лицензии CC BY 4.0 в начале каждого модуля — сохранять.
- Области кода: `#Область ПрограммныйИнтерфейс` (экспортные), `#Область СлужебныеПроцедурыИФункции`, `#Область ОбработчикиСобытий` — соблюдать порядок.
- Экспортные процедуры/функции помечаются `Экспорт` и снабжаются doc-комментарием с разделом `Параметры:` (типы через `-` на отдельных строках).
- Запросы — на языке запросов 1С, конкатенация строк запроса через `<<КодЗапроса>>` в типовых процедурах БСП не используется; текст запроса — строковый литерал.
- Имена: `КэмелКейс` на русском, без подчеркиваний (кроме префикса `_Демо`).

## Принципы разработки

Код доработок пишется по принципам **SOLID**, **DRY**, **KISS**:

- **SOLID** — один модуль или процедура = одна ответственность; расширение поведения через переопределяемые модули БСП и расширения, а не правку существующего кода.
- **DRY** — дублирование кода недопустимо; общий код выносится в отдельные процедуры и общие модули, в приоритете готовые механизмы БСП.
- **KISS** — минимальное достаточное решение; никаких абстракций и настроек «на будущее».

## Доработки и расширения

**Все доработки конфигурации выполняются в расширениях (если явно не указано иное).** Основная конфигурация — поставляемая БСП, ее не изменять.

Расширения лежат в `extensions/<ИмяРасширения>/`; эталоны — `extensions/_ДемоПустоеРасширение/` и `extensions/_ДемоРасширение/`. Режим совместимости расширения должен совпадать с основной конфигурацией (`Version8_5_1`) — проверять при создании и правке; у обоих эталонов он уже `Version8_5_1`. Обязательный состав, заимствование объектов, роли и права, загрузка в Конфигуратор и ловушки формата выгрузки — скилл `make-extension` (`.zcode/skills/make-extension/SKILL.md`); подключать его при любой работе с расширениями.

## Скиллы superpowers

Библиотека скиллов [superpowers](https://github.com/obra/superpowers) (MIT) установлена в `.zcode/skills/` рядом с проектными скиллами (`bsl-*`, `make-*`). В начале сессии, перед любой нетривиальной задачей, читать `.zcode/skills/using-superpowers/SKILL.md` и следовать ему: подбирать подходящий скилл под задачу (brainstorming — до проектирования нового, writing-plans/executing-plans — для многошаговых доработок, test-driven-development — для кода, systematic-debugging — при отладке, verification-before-completion — перед отчетом о завершении) и подключать его чтением его `SKILL.md`. Обязательные workflows, а не рекомендации. Отступать от них только по явной команде пользователя. Проектные скиллы 1С (`make-extension` и др.) приоритетны в своей области; скиллы superpowers — по инженерному процессу.

## Сборка и проверка

Это выгрузка, а не собираемый проект — «сборки» в привычном смысле нет. Жизненный цикл изменений:

- **Загрузка в Конфигуратор**: Конфигуратор → «Загрузить конфигурацию из файлов» → корень репозитория. Обратная операция — «Сохранить конфигурацию в файлы» (обновляет `ConfigDumpInfo.xml`).
- **Проверка синтаксиса**: в Конфигураторе «Проверка конфигурации» (Ctrl+F7 в конфигураторе после загрузки); автономной CLI-проверки BSL в репозитории нет.
- **Запуск**: демо-конфигурация запускается в режиме управляемого приложения платформы 8.5.1+.

Текстовые правки (код, строки интерфейса) допустимы прямо в файлах выгрузки; структурные изменения состава метаданных делаются в Конфигураторе с последующим сохранением выгрузки обратно в репозиторий.

## Запрещенные действия

При работе с информационной базой и Конфигуратором:

- **Никогда не завершать сеансы пользователей.** Даже если операция требует монопольного режима (обновление конфигурации базы данных, загрузка конфигурации из файлов) — не завершайте активные сеансы и не принуждайте базу к монопольному режиму. Если операция блокируется работающими пользователями — сообщите об этом и дождитесь явного решения пользователя.
- **Не применять расширения автоматически.** Применение расширения к информационной базе (загрузка расширения, «Обновить конфигурацию базы данных», установка режима безопасного режима и защиты от опасных действий) выполняется только по явной команде пользователя. Без команды — только подготовка и правка файлов расширения в `extensions/`.

## Работа с веб-поиском

Если при выполнении задачи использовался веб-поиск или чтение веб-страниц (1С:ИТС, ИТС.1С, документация платформы, форумы и т.п.), в конце ответа всегда приводите раздел «Sources:» со списком markdown-ссылок на все ресурсы, которые использовались при подготовке ответа. Это требование пользователя: он должен иметь возможность проверить первоисточники.
