# Этап 5: `POST /object` — создание

Источник: docs/superpowers/plans/2026-11-04-objects-service.md («Этап 5»).
Спецификация: docs/superpowers/specs/2026-11-04-objects-service-design.md
(«Создание», «Ошибки и журналирование», «Разрешение на создание») — при
расхождении приоритет у спецификации. Это последний этап реализации: после него
мостов в коде не остаётся.

**Files:**
- Modify: `src/extensions/СчетаМагазина/CommonModules/СчетаМагазинаДанные/Ext/Module.bsl`
- Modify: `src/extensions/СчетаМагазина/CommonModules/СчетаМагазинаМетаданные/Ext/Module.bsl`
- Modify: `src/extensions/СчетаМагазина/HTTPServices/СчетаМагазина/Ext/Module.bsl` (обработчик `СоздатьОбъект`)
- Test: `src/tests/objects.http` (секции «Создать объект», «Отказ по обязательному полю»)

**Interfaces:**
- Consumes (готово, Экспорт): `ТипПоИмени`, `ДопустимКСозданию`, `Схема(Мета)`,
  `ОписаниеТипа`, `НайтиОписание`, `УникальныйИдентификаторИзСтроки`,
  `НайтиОбъекты`, `Кратко(Объект, Мета, Вид)`, `СсылкаДоступна(Мета, Ссылка)`;
  в HTTP-модуле — `ОтветJSON`, `ОшибкаJSON`, `ОтказJSON`, `ОшибкиЗаполнения`,
  `ПутьПоля`, `Цифры`, `ЭтоНарушениеПрав`, `НепредвиденнаяОшибка`.
- Produces: все пять маршрутов контракта работают.

**Обязательные решения контроллера (рулинги):**
1. **Мосты удаляются в этом этапе**: после параметризации `Подготовить`
   вызовы `Документ()`/`Схема()` в `СчетаМагазинаДанные` исчезают — удалить
   `Документ()` и делегат `Схема()` из `СчетаМагазинаМетаданные` (этап 2
   отложил это сюда сознательно).
2. **UUID строго в нижнем регистре** и при записи (существующее поведение
   `УникальныйИдентификаторИзСтроки`); тела запросов в objects.http — с
   нижним регистром.
3. `ДопустимКСозданию(Мета)` дополнить: `false` для справочника с составным
   владельцем или владельцем-документом (спецификация «Группы и подчинённые
   справочники»).
4. Minor из ревью этапа 2, сделать попутно: выровнять отступы веток
   `ОписаниеТипа`; read-only стандартным реквизитам — единый `reason`
   (например «Поле недоступно для записи через этот сервис») вместо разнобоя.
5. Создание группы контрактом не достижимо (`ЭтоГруппа` read-only) — это и
   есть отказ; специального кода не вводить, в отчёте зафиксировать «по
   построению».

**Шаги:**

- **5.1 Запросы этапа в objects.http** (секции «Создать объект» и «Отказ по
  обязательному полю», стиль файла, разделители `###`; все UUID — из `.env`
  через `{{$dotenv ИМЯ}}`, нижний регистр не гарантирован в .env — в теле
  JSON значения подставляются как есть из .env, сервис примет их как есть;
  если в .env верхний регистр — оставить и зафиксировать факт в отчёте):
  1. `POST …/object` — счёт: `{"type":"Документ._ДемоСчетНаОплатуПокупателю",
     "header":{"Дата":"2026-11-04T12:00:00","Организация":{{$dotenv
     ORGANIZATION_ID}},"Партнер":{{$dotenv PARTNER_ID}},"Контрагент":{{$dotenv
     COUNTERPARTY_ID}},"Подразделение":{{$dotenv DEPARTMENT_ID}},
     "Ответственный":{{$dotenv RESPONSIBLE_ID}},"ВалютаДокумента":{{$dotenv
     CURRENCY_ID}}},"tables":{"Товары":[{"Номенклатура":{{$dotenv PRODUCT_ID}},
     "Цена":100,"Сумма":100,"Всего":100}]}}` (имена полей сверить с
     `/type?name=Документ._ДемоСчетНаОплатуПокупателю`; JSON-строки в кавычках,
     `Content-Type: application/json`);
  2. `GET …/search?type=Документ._ДемоСчетНаОплатуПокупателю&q=<номер из
     ответа предыдущего запроса>` — вставить фактический номер вручную после
     первого прогона;
  3. `POST` справочник: `{"type":"Справочник._ДемоПартнеры","header":{"Наименование":"Тестовый партнер HTTP"},"tables":{}}`;
  4. `POST` справочник вне `_Демо*`: `{"type":"Справочник.Валюты","header":{"Наименование":"Тестовая валюта HTTP"},"tables":{}}`
     (если у `Валюты` по `/type` есть `required=true` поля — передать
     минимально необходимые из поиска/схемы, не выдумывать);
  5. `POST` служебный вид: `{"type":"Справочник.Пользователи","header":{},"tables":{}}`;
  6. `POST` счёта без `Организация`;
  7. `POST` счёта с `"Дата":"2026-01-01T00:00:00Z"`;
  8. `POST` счёта с неизвестным полем `"ЛожноеПоле"`.

- **5.2 RED**: прогнать все 8 curl-ом (POST — с `Content-Type` и телом из
  файла/здесь-документа), ожидание `501` (заглушка `СоздатьОбъект`).
  Записать ответы.

- **5.3 Реализовать разбор и допуски** (обработчик `СоздатьОбъект`, порядок
  проверок): `Content-Type` начинается с `application/json` → иначе
  `415 unsupported_media_type`; полный разбор JSON (`ЧтениеJSON`): после
  первого значения — только пробельные символы до конца → иначе
  `400 invalid_request`; `type` — `ТипПоИмени` → иначе `400 unknown_type`;
  `ДопустимКСозданию` (в дополненном виде, рулинг 3) → иначе
  `403 creation_not_allowed`.

- **5.4 Реализовать создание** по порядку спецификации «Создание»:
  - `Подготовить(Данные, Мета, Ошибки) → {header, tables}` — параметризация
    существующей `Подготовить(Данные, Ошибки)`: схема из `Схема(Мета)`, мета
    передаётся; проверка структуры `header`/`tables` (обязательны), неизвестные
    ключи/поля/таблицы — ошибки с путями (`header.Поле`, `tables.ТЧ[i].Поле`);
    `Преобразовать` дополнить веткой `kind = "document"` для ссылок (мета из
    описания типа, `СсылкаДоступна` по документной таблице);
  - создать объект менеджером вида (`Документы[X].СоздатьДокумент()` /
    `Справочники[X].СоздатьЭлемент()`) — обработку заполнения НЕ вызывать
    (`Заполнить(Данные, …)` платформенную не вызывать), значения за
    пользователя не подставлять; требуемые обязательные — из запроса;
  - в транзакции (`НачатьТранзакция`…`ЗафиксироватьТранзакция`): перенос
    шапки/строк (`Заполнить(Объект, Данные)`), очистка очереди сообщений
    (`ОбменДанными.Загрузка` тумблер) и штатная `ПроверитьЗаполнение(Объект)`
    — отказ: `ОтменитьТранзакция` и `422 validation_failed` со ВСЕМИ
    сообщениями через `ОшибкиЗаполнения`/обобщённый `ПутьПоля` (`path = null`,
    если поле не определено); иначе запись без проведения (документ —
    `Записать(РежимЗаписиДокумента.Запись)`, справочник — `Записать()`),
    после записи проверка `Проведен = Ложь`; ответ `201` —
    `Кратко(Объект, Мета, Вид)`; исключение — `ОтменитьТранзакция` и
    `НепредвиденнаяОшибка` (403/500 по категории);
  - `ПутьПоля` обобщить по `Схема(Мета)` (сейчас жёстко `Схема()` — мост);
  - подготовка ответа до завершения транзакции.

- **5.5 Удалить мосты** (`Документ()`, делегат `Схема()` в
  `СчетаМагазинаМетаданные`) — после шага 5.4 ни одного вызова не осталось
  (проверить grep-ом по расширению). Minor-чистки из рулинга 4.

- **5.6 Формат файлов**: BOM + CRLF байтово (полная перезапись; первые байты
  239,187,191 ровно один раз; голых LF нет).

- **5.7 Загрузка расширения** (разрешено): `tasklist /fi "IMAGENAME eq
  1cv8.exe"`; команда как в этапе 1, лог `%TEMP%\objects-load-5.log`; таймаут
  600000 мс; при таймауте — STOP, BLOCKED; успех подтверждает только 5.8.

- **5.8 GREEN**: ожидание (по каждому из 8 запросов):
  1. счёт — `201`, `posted: false`, `number` заполнен;
  2. поиск по номеру — `200`, `items` содержит `id` созданного счёта;
  3. партнёр — `201` с `code`;
  4. `Валюты` — `201` (допуск вне `_Демо*` подтверждён);
  5. `Пользователи` — `403 creation_not_allowed`;
  6. счёт без `Организация` — `422`, `details` содержит
     `path = "header.Организация"` (или `null` с текстом штатной проверки —
     записать как есть);
  7. дата с `Z` — `400 invalid_request`;
  8. неизвестное поле — `400` с `path = "header.ЛожноеПоле"`;
  плюс регрессия: `/types`, `/type`, `/search`, `GET /object` по `id` из
  ответа 1 — `200`, `posted: false`.
  Побочный эффект: в базе появились тестовые объекты «Тестовый партнер HTTP»,
  «Тестовая валюта HTTP» и тестовый счёт — это контрольные примеры приёмки,
  НЕ удалять (этап 6 показывает их пользователю). Записать фактические ответы.

**Глобальные ограничения:** те же (правки в четырёх файлах брифа; русский BSL
без «ё»; UTF-8 BOM + CRLF; XML не трогать; основную конфигурацию не менять;
привилегированный режим не включать; записи через штатные обработчики —
запись с флагом обмена запрещена; коммитов нет).
