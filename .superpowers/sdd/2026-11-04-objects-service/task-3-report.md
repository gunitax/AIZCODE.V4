# Отчёт по этапу 3: `GET /search` — поиск

**Статус: DONE_WITH_CONCERNS** (все проверки GREEN выполнены; одно отклонение
имени типа из брифа — как на этапе 1; см. «Concerns»).

## Что реализовано

### Обработчик `НайтиОбъекты(Запрос)` (HTTPServices/СчетаМагазина/Ext/Module.bsl)

Заглушка 501 заменена реализацией; порядок проверок по брифу 3.3:

1. `type` — `Строка(Запрос.ПараметрыЗапроса.Получить("type"))`; отсутствует или
   `ТипПоИмени` не распознал → `ОтказJSON(400, "unknown_type", "Тип не найден
   среди поддерживаемых видов Справочник и Документ: <name>")` (текст и стиль —
   как у `ОписатьТип`, этап 2);
2. `q` — `СокрЛП(Строка(…Получить("q")))`; пустая после обрезки →
   `ОтказJSON(400, "invalid_request", "Строка поиска пуста")` — details:
   `[{"path": null, "message": "Строка поиска пуста"}]` (путь null —
   предсуществующий дефолт `ОтказJSON`);
3. `limit` — необязательный, по умолчанию 20; непустой проверяется помощником
   `Цифры` (только цифры; пустая/отсутствующая строка означает «не задан»),
   затем `Число` и диапазон 1–100; любое нарушение →
   `ОтказJSON(400, "invalid_request", "limit — целое число от 1 до 100")`;
   диапазон и не-число проверяются раздельно (в 1С «Или» не браншируется —
   `Число("abc")` бросил бы исключение);
4. нет права `ПравоДоступа("Чтение", Данные.Мета)` → `ОтказJSON(403,
   "forbidden", "Недостаточно прав на операцию")`;
5. успех — `ОтветJSON(200, СчетаМагазинаДанные.НайтиОбъекты(Данные.Мета,
   Данные.kind, СтрокаПоиска, Лимит))`.

Остальные обработчики не тронуты (`НеРеализовано` осталась для `/object` и
`POST /object` — этапы 4–5).

### `СчетаМагазинаДанные/Ext/Module.bsl`

- `НайтиОбъекты(Мета, Вид, СтрокаПоиска, Лимит) Экспорт → {items, hasMore}` —
  переработка `НайтиВСправочнике` (удалена; её allowlist-разрешение меты и
  защитное исключение больше не нужны: доступ проверяет обработчик):
  - поле поиска и таблица по виду: `Номер`/`Документ.X` при `Вид = "document"`,
    иначе `Наименование`/`Справочник.X`;
  - текст запроса: `ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ <Лимит+1> Ссылка, <поле> ИЗ
    <таблица> ГДЕ НЕ ПометкаУдаления [И НЕ ЭтоГруппа] И <поле> ПОДОБНО &Шаблон
    СПЕЦСИМВОЛ "~" УПОРЯДОЧИТЬ ПО <поле>, Ссылка`; `НЕ ЭтоГруппа` добавляется
    только справочнику (как `УсловиеЭлементов`, документ неиерархичен — вызов
    для документа пропущен ветвлением, не `?(…)` — оба аргумента `?(…)`
    вычисляются);
  - шаблон — `"%" + ОбщегоНазначения.СформироватьСтрокуДляПоискаВЗапросе(
    СтрокаПоиска) + "%"` (механика прежнего кода сохранена: `% _ [ ^` —
    литералы, `*` → `%`, пробелы → `%`);
  - элемент — `Новый Структура("id,name", …)`, `name` — `Строка(Выборка[ПолеПоиска])`;
    `hasMore=true`, когда после `Лимит` записей выборка не исчерпана.
- `СсылкаДоступна(Мета, Ссылка) Экспорт → Булево` — обобщена: право
  `Чтение` на мету; таблица по виду (идиом
  `Метаданные.Справочники.Найти(Мета.Имя) = Мета`); запрос
  `ВЫБРАТЬ РАЗРЕШЕННЫЕ Ссылка ИЗ <таблица> ГДЕ Ссылка = &Ссылка И НЕ
  ПометкаУдаления [+ НЕ ЭтоГруппа у справочника]`; попытка/перехват нарушения
  прав сохранены. Ранее была не-экспортной с allowlist-сигнатурой `(Имя,
  Ссылка)`.
- `Преобразовать`, ветка `kind = "catalog"`: вызов обновлён —
  `СсылкаДоступна(Метаданные.Справочники[Описание.catalog], Результат)`; мета
  резолвится из описания типа, не из пользовательской строки; остальная
  механика ветки прежняя.

### GREEN (шаг 3.7, после загрузки; curl.exe, те же URL, что в RED)

**1. `q=Альфа` по `Справочник._ДемоПартнеры` — HTTP 200.** Тело:

```json
{"items": [{"id": "9203492b-ea3e-11de-8634-001d600d9ad2", "name": "ООО \"Альфа\""}], "hasMore": false}
```

`id` совпадает с `PARTNER_ID` из `.env` — ожидание брифа выполнено.

**2. `q=%` — HTTP 200**, `{"items": [], "hasMore": false}` — символы шаблона
литеральные (в наименованиях демо-базы `%` нет).

**3. `limit=0` — HTTP 400**, код `invalid_request`, сообщение «limit — целое
число от 1 до 100», details path=null.

**4. `limit=101` — HTTP 400**, тот же `invalid_request`.

**5. `limit=abc` — HTTP 400**, тот же `invalid_request` (не-число отсечено
`Цифры`, до `Число` не дошло).

**6. без `q` — HTTP 400**, `invalid_request`, «Строка поиска пуста», path=null.

**7. `type=ТакогоНет&q=а` — HTTP 400**, `unknown_type`: «Тип не найден среди
поддерживаемых видов Справочник и Документ: ТакогоНет».

**8. `Справочник.Пользователи&q=а` — HTTP 200**, 14 элементов (`Администратор`,
`Либерзон Мария Робертовна (менеджер отдела продаж)`, …), отсортированы по
наименованию, `hasMore=false` — «читаемо пользователем», allowlist-ограничения
больше не действуют.

**9. документ `q=0&limit=1` — HTTP 200**, тело:
`{"items": [{"id": "c5f6a3fc-ca6c-11e1-8c36-080027007001", "name":
"НТ00-А00001"}], "hasMore": true}` — поиск по номеру, выборка не исчерпана
(`hasMore=true` при `limit=1`). Тип в запросе — `Документ._ДемоРеализацияТоваров`
(см. Concerns п. 1: `_ДемоРеализацияТоваровУслуг` в базе нет).

**Регрессия этапов 1–2 после загрузки:** `GET /types` → **200**;
`GET /type?name=Справочник._ДемоПартнеры` → **200**;
`GET /type?name=Документ._ДемоСчетНаОплатуПокупателю` → **200**;
`GET /type?name=ТакогоНет` → **400** `unknown_type`. Оба общих модуля
компилируются (удаление allowlist-функций ничего не сломало).

## Self-review

- Все 7 шагов брифа выполнены; фактические RED/GREEN записаны выше.
- После удаления allowlist-функций grep по расширению: 0 вхождений
  `РазрешенныеСправочники|ДобавитьСправочники|НайтиВСправочнике`.
- Этапы 1–2 не сломаны: `/types` и `/type` отвечают 200 после загрузки (см.
  GREEN, блок «Регрессия»).
- Кодировка байтово: BOM ровно один, голых LF нет, хвост CRLF во всех четырёх
  файлах; двойной BOM инцидента этапа 2 не повторён (правки точечные,
  перезапись целиком не понадобилась).
- Сигнатуры точно из брифа: `НайтиОбъекты(Мета, Вид, СтрокаПоиска, Лимит)`
  и `СсылкаДоступна(Мета, Ссылка)`, обе `Экспорт` (этап 5 их использует).
- Регистр вида: `ТипПоИмени` не менялся («Справочник»/«Документ» с заглавной,
  каноническое сравнение — как на этапе 1); `НайтиОбъекты`/`СсылкаДоступна`
  сравнивают `Вид = "document"` канонически.
- «ё» в новом коде нет (проверено по трём `.bsl` и objects.http; предсуществующие:
  «ещё не реализован» в `НеРеализовано` — нужна заглушкам этапов 4–5, и
  «задаёт» в комментарии POST-секции objects.http вне моей секции).
- YAGNI: ничего сверх брифа — без пагинации, без поиска по нескольким видам,
  без кэширования; параметры читаются только из `ПараметрыЗапроса`.

## Concerns

1. **`Документ._ДемоРеализацияТоваровУслуг` не существует в базе** — как и
   `_ДемоПоступлениеТоваровУслуг` на этапе 1 (тогда фактический тип оказался
   `_ДемоПоступлениеТоваров`). В этой выгрузке есть только
   `Документ._ДемоРеализацияТоваров` (подтверждено `src/Documents/` и полным
   реестром типов этапа 1: 24 демо-документа, «РеализацияТоваровУслуг» нет ни
   в основной конфигурации, ни в расширении). Запрос этапа и GREEN выполнены на
   фактическом типе `Документ._ДемоРеализацияТоваров` (смысл проверки —
   документ-поиск по фрагменту номера `0` с `limit=1` — воспроизведён: 200,
   находка, `hasMore=true`). Контроллеру: поправить имя в плане/брифе (шаги
   3.1/3.7), чтобы этапы 5–6 не ссылались на несуществующий тип.
2. `ПравоДоступа("Чтение", …)` в обработчике возвращает 403 до запроса;
   дополнительный перехват нарушения прав в `СсылкаДоступна` сохранён из
   прежней версии (RLS-условия могут урезать выборку на уровне запроса). Оба
   слоя — прежняя механика, не новая абстракция.
3. Чекбоксы 3.1–3.7 плана не отмечал — правки только в файлах брифа; факты
   RED/GREEN фиксирует этот отчёт (отметить — на контроллере).
