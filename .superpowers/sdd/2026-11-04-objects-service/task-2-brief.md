# Этап 2: `GET /type` — схема типа

Источник: docs/superpowers/plans/2026-11-04-objects-service.md («Этап 2»).
Спецификация: docs/superpowers/specs/2026-11-04-objects-service-design.md
(«Описание типов», «Разрешение на создание», «Поддерживаемые виды и типы
значений») — при расхождении приоритет у спецификации.

**Files:**
- Modify: `src/extensions/СчетаМагазина/CommonModules/СчетаМагазинаМетаданные/Ext/Module.bsl`
- Modify: `src/extensions/СчетаМагазина/HTTPServices/СчетаМагазина/Ext/Module.bsl` (обработчик `ОписатьТип`)
- Test: `src/tests/objects.http` (секция «Описать тип»)

**Interfaces:**
- Consumes (готово с этапа 1, Экспорт): `ИмяТипа(Мета)`, `ТипПоИмени(ИмяТипа)`
  → `{Мета, kind}`, `ДопустимКСозданию(Мета)`.
- Produces (этапы 3–5, Экспорт):
  - `Схема(Мета) → Структура` — `{type, kind, title, creatable, fields,
    tables, rules}`; параметры по спецификации:
    - `type` — `"Справочник.X"` / `"Документ.X"`; `kind` — `"catalog"`/`"document"`;
      `title` — `Представление()`; `creatable` — `ДопустимКСозданию(Мета)`;
    - правила стандартных реквизитов справочника: `Код` — `writable=false`
      (reason «назначает 1С»); `Наименование` — записываемо, если длина по
      квалификатору > 0; `ПометкаУдаления`, `ЭтоГруппа` — только чтение;
      `Родитель` — `writable=false`, reason «группы не поддерживаются»;
      `Владелец` (у подчинённого) — обычное описываемое поле;
    - правила стандартных реквизитов документа: `Дата` — записываема и
      `required=true` (правило сервиса); `Номер` — `writable=false` (назначает
      1С); `Проведен`, `ПометкаУдаления` — только чтение (вне рамок сервиса);
    - `required` прикладных полей — из `ПроверкаЗаполнения`; у табличной части —
      из её настройки; стандартные реквизиты (кроме `Дата`) — `required=false`;
    - таблицы, обслуживаемые БСП, — закрытый список имён
      `ОбслуживаемаяБСПТаблица(ИмяТаблицы) → Булево`:
      `ДополнительныеРеквизиты`, `КонтактнаяИнформация` → `writable=false` с
      reason (текст — «Табличная часть обслуживается механизмами БСП»);
    - неподдерживаемый тип значения у поля → поле целиком `writable=false` с
      `reason` (правило существующего `ОписаниеПоля` — сохранить);
    - `rules` — объект с пояснениями из спецификации: окончательное решение за
      штатной проверкой заполнения; даты ISO 8601 без зоны, местное время базы;
      `null` — штатное пустое значение; документ создаётся непроведённым;
      суммы и значения по умолчанию сервис не рассчитывает.
  - `ОписаниеТипа(ТипПоля, ОписаниеТиповПоля)` дополнить веткой ссылок на
    документы: `name = "DocumentRef.X"`, `kind = "document"`, `document = X`,
    `searchUrl = "/search?type=Документ.X"`. Ссылки на справочники — как есть
    (`catalog` + `searchUrl = "/search?type=Справочник.X"` — обновить старый
    `/catalogs/X` на актуальный маршрут).

**Мосты (решение контроллера — нарушение буквы плана 2.3 «удалить»):**
`Документ()` и старую безпараметрическую `Схема()` НЕ удалять: `СчетаМагазинаДанные`
(`Подготовить`, `Прочитать`) и `Реквизит()` вызывают их до своих этапов (4–5).
`Схема()` переделать в делегат: `Возврат Схема(Документ());`.
Удаление мостов — этап 5. Остальные существующие функции (`РазрешенныеСправочники`,
`ОписаниеПоля`, `ОписаниеТипа`, `ДобавитьСправочники`, `ДобавитьСправочники`,
функции этапа 1) — не трогать, кроме прямо указанного (`ОписаниеТипа` — ветка
document; `ОписаниеПоля` — только если нужно для passing Мета; механика прежняя).

**Steps:**

- **2.1 Запросы этапа в objects.http** (секция «Описать тип», стиль файла
  сохранить, разделители `###`): `GET {{$dotenv OBJECTS_URL}}/type?name=Справочник._ДемоПартнеры`;
  `?name=Документ._ДемоСчетНаОплатуПокупателю`; `?name=Справочник.Пользователи`;
  `?name=ТакогоНет`.

- **2.2 RED**: прогнать curl-ом (Authorization из `.env`), ожидание `501`
  (заглушка). Записать фактические ответы.

- **2.3 Реализовать**: параметризовать `Схема(Мета)`; мост `Схема()` (см. выше);
  `ОбслуживаемаяБСПТаблица(ИмяТаблицы)`; правила стандартных реквизитов по виду
  (таблица выше); ветка `document` в `ОписаниеТипа`; обновить `searchUrl`
  справочных ссылок на `/search?type=…`.

- **2.4 Реализовать `ОписатьТип(Запрос)`**: параметр `name` из
  `Запрос.ПараметрыЗапроса` (не `ПараметрыURL` — параметры шаблона там);
  отсутствует или `ТипПоИмени` вернул `Неопределено` → `400` через `ОтказJSON`
  с `error.code = "unknown_type"`; иначе `200` — `ОтветJSON(200, Схема(Мета))`.

- **2.5 Формат файлов**: BOM + CRLF, нормализация как в этапе 1 (шаг 1.5).

- **2.6 Загрузка расширения** (разрешено): `tasklist /fi "IMAGENAME eq 1cv8.exe"`;
  команда как в этапе 1, лог `%TEMP%\objects-load-2.log`; таймаут 600000 мс;
  при таймауте — STOP, BLOCKED (не ретраить); пустой `/Out` — не признак;
  успех подтверждает только 2.7.

- **2.7 GREEN**: ожидание:
  - `Справочник._ДемоПартнеры` — `200`; таблица `КонтактнаяИнформация`
    `writable=false` с `reason`; `creatable=true`;
  - `Документ._ДемоСчетНаОплатуПокупателю` — `200`; поле `Дата`
    `required=true`, `writable=true`; `Номер` `writable=false` с `reason`;
  - `Справочник.Пользователи` — `200`, `creatable=false`;
  - `ТакогоНет` — `400`, `error.code = "unknown_type"`.
  Записать фактические ответы.

**Глобальные ограничения:** те же, что в этапе 1 (три файла; русский BSL без
«ё»; UTF-8 BOM + CRLF; XML не трогать; основную конфигурацию не менять;
коммитов нет).
