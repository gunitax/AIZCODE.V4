### `СчетаМагазинаМетаданные` (CommonModules/СчетаМагазинаМетаданные/Ext/Module.bsl)

Добавлены в конец модуля, существующие функции (`Документ()`, `Схема()`, `ОписаниеПоля()`, `ОписаниеТипа()`, `РазрешенныеСправочники()`, `ДобавитьСправочники()`) не тронуты:

- `ИмяТипа(Мета) Экспорт → Строка` — `"Справочник.X"` / `"Документ.X"` (определение вида через `Метаданные.Справочники.Найти(Мета.Имя) = Мета`, как в существующем коде модуля);
- `ТипПоИмени(ИмяТипа) Экспорт → Структура|Неопределено` — разбор `Вид.Имя` через `СтрРазделить`, поиск в `Метаданные.Справочники`/`Метаданные.Документы`; возвращает `Новый Структура("Мета,kind", Мета, Вид)`, `kind = "catalog"|"document"`; нераспознанное (не 2 части, вид не Справочник/Документ, имя не найдено) → `Неопределено`;
- `РеестрТипов() Экспорт → Массив` — перебор `Метаданные.Справочники` (`kind = "catalog"`), затем `Метаданные.Документы` (`kind = "document"`); каждая запись — `{name, kind, title, creatable}`, `title = Мета.Представление()`;
- `ДопустимКСозданию(Мета) Экспорт → Булево` — `СтрНачинаетсяС(Мета.Имя, "_Демо") Или Мета.Имя = "Валюты"` (точно по брифу);
- `ЗаписьРеестра(Мета, Вид)` — внутренняя (не Экспорт), собирает запись реестра (DRY между двумя коллекциями).

### Обработчик `НайтиТипы` (HTTPServices/СчетаМагазина/Ext/Module.bsl)

- `q` — `Запрос.ПараметрыЗапроса.Получить("q")`, `СокрЛП`, сравнение без учёта регистра (`ВРег` обеих сторон);
- пустой/отсутствующий `q` — все виды; иначе фильтр: вхождение в `name` или `title`;
- сортировка по `name` (через `ТаблицаЗначений.Сортировать("name Возр")`, помощник `СортироватьПоИмени`);
- ответ `200` через существующий `ОтветJSON(200, Новый Структура("types", …))`.

Точная строка чтения параметра: `Шаблон = ВРег(СокрЛП(Строка(Запрос.ПараметрыЗапроса.Получить("q"))));` — `Строка()` отрабатывает отсутствие параметра (`Неопределено` → `""`). Помощник `СортироватьПоИмени(Записи)` — внутренний, в том же модуле под обработчиком.

Остальные обработчики (`ОписатьТип`, `НайтиОбъекты`, `ПрочитатьОбъект`, `СоздатьОбъект`) — прежние заглушки 501, не тронуты.

## Self-review findings, issues, concerns

1. **База не содержит `Документ._ДемоПоступлениеТоваровУслуг`.** Фактический тип — `Документ._ДемоПоступлениеТоваров` (подтверждено выгрузкой репозитория и ответом сервиса). Бриф и спецификация ссылаются на несуществующее имя; Green-проверка выполнена на фактическом типе (совпадение по той же подстроке). Контроллеру: поправить имя в спецификации/плане/objects.http-ожиданиях, прежде чем на него будет ссылаться этап 2 (`/type`) — там в запросах этапа этого имени нет (используется `Документ._ДемоСчетНаОплатуПокупателю`, он существует), но тексты брифов/спеки вводят в заблуждение.
2. **Параметры строки запроса на этой платформе — `Запрос.ПараметрыЗапроса`, не `ПараметрыURL`.** Первая реализация (по привычной идиоме `ПараметрыURL`) дала неотфильтрованный полный список: `ПараметрыURL` содержит только параметры, параметризованные в шаблоне URL (подтверждено БСП: `src/InformationRegisters/ВременныеИдентификаторыЗапросов/Ext/ManagerModule.bsl:30-31` и комментарием к структуре: «ПараметрыURL — части URL-адреса, которые были параметризованы в шаблоне», «ПараметрыЗапроса — параметры запроса»). Исправлено и перезагружено. **Для этапов 2–5: читать `name`, `type`, `q`, `limit`, `id` из `Запрос.ПараметрыЗапроса`.** Процент-кодированная кириллица декодируется корректно (совпадение «валют» → «Валюты» по `ВРег` сработало).
3. **Предсуществующий «ё» в тексте заглушки** `НеРеализовано` («ещё не реализован») — вне шага 1.4 (заглушки этапов 2–5 и их помощник я не трогал по ограничению «правки только в трёх файлах»/шагам брифа); исчезнет при замене заглушек этапами. Мой код «ё» не содержит (проверено: «Возр», «ЗаписьРеестра», «СортироватьПоИмени» и т.д.).
4. `РеестрТипов()` возвращает естественный порядок (справочники, затем документы) — сортировку по `name` делает обработчик (по брифу 1.4); запись реестра собирает внутренняя `ЗаписьРеестра` (не Экспорт — интерфейс этапа исчерпывается четырьмя функциями).
5. Чекбоксы 1.1–1.7 в `docs/superpowers/plans/2026-11-04-objects-service.md` не отмечал — ограничение этапа «правки только в трёх файлах»; факты RED/GREEN фиксирует этот отчёт (отметить — на контроллере).
6. XML расширения, основная конфигурация, привилегированный режим — не затронуты. Коммитов нет (каталог не git-репозиторий).
